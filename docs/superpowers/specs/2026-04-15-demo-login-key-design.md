# 演示密匙登录设计

## 目标

为登录页增加一个“演示密匙”登录入口。用户输入预先配置的密匙后，
后端校验通过即签发现有 JWT，前端后续仍沿用当前会话机制。

本次演示场景要求保留现有 `Space` 登录入口，并把登录页品牌名统一改为
`传奇bot`，同时删除底部“隐私政策 / 数据收集政策”外链文案。

## 范围

- 新增后端配置 `system.demo_login_key`
- 新增后端接口 `/api/v1/user/auth-key`
- 登录页在配置了演示密匙时展示单输入框密匙登录
- 已存在 `Space` 登录时，密匙登录与 `Space` 登录并存展示
- 密匙登录成功后进入当前系统第一个用户，不新增独立体验账号
- 登录页品牌文案改为 `传奇bot`
- 删除登录页底部“隐私政策 / 数据收集政策”文案与链接

## 非目标

- 不改动 JWT 结构
- 不改动登录后页面的鉴权方式
- 不把全站接口切换为 API Key 鉴权
- 不新增用户表字段或独立“体验账号”体系

## 方案

后端读取 `system.demo_login_key`，新增密匙登录校验逻辑。校验通过后，
直接以当前系统第一个用户身份签发现有 JWT。前端通过
`/api/v1/user/account-info` 感知演示密匙是否启用；若启用，则在登录页
显示密匙输入框并调用新接口。

登录页展示逻辑按账号类型和配置开关组合处理：

- 当首个账号是 `space` 账号时，继续展示 `通过 Space 登录`
- 当 `system.demo_login_key` 非空时，额外展示 `通过密匙登录`
- 两种方式同时存在时，中间使用现有 `或` 分隔线
- 密匙登录成功后，后端直接为当前系统第一个用户签发 JWT，因此登录后的
  用户身份与当前主账号保持一致

品牌与文案调整：

- 登录页中出现的 `LangBot` 品牌文案改为 `传奇bot`
- 欢迎语改为 `欢迎回到 传奇bot 👋`
- 删除底部协议提示区块，不再展示“继续即表示您同意我们的 隐私政策 和
  数据收集政策”

错误处理策略：

- 密匙为空：前端表单校验提示“请输入密匙”
- 密匙错误：提示“登录失败，请检查密匙是否正确”
- 后端不可达：继续沿用现有“无法连接到服务器”
- 系统未初始化：不允许通过密匙获取登录态

## 风险控制

- 仅当配置项非空时启用演示密匙入口
- 密匙错误返回明确失败信息
- 系统未初始化时禁止密匙登录
- 不触碰现有登录后业务接口，降低演示风险
- 不移除现有 `Space` 登录，避免影响当前主流程

## 验收标准

- 配置 `system.demo_login_key` 后，登录页同时出现 `通过 Space 登录` 与
  `通过密匙登录`
- 未配置 `system.demo_login_key` 时，不展示密匙登录入口
- 输入正确密匙后，成功进入当前系统现有主账号
- 输入错误密匙后，停留在登录页并提示失败
- 登录页中不再出现 `LangBot`，统一改为 `传奇bot`
- 登录页中不再出现“隐私政策 / 数据收集政策”文案和链接
